Git 新手速成：从 add/commit/push 到撤销后悔药

面向只会 git add . / git commit -m / git push 三件套的新手，讲清楚 Git 的三个区域，以及常用的查看、撤销、回退指令。

一、先搞懂三个区域

Git 的核心其实是三个”地方”，你的文件改动在里面层层流转：

  • 工作区：磁盘上你正在编辑的文件本身。
  • 暂存区：”下次 commit 要打包哪些内容”的清单。git add 就是往清单里放东西。
  • 提交历史：git commit 把暂存区的内容打包成一条提交记录；git push 之后才真正到 GitHub。

暂存区存在的意义：让你可以只提交一部分改动。比如改了 5 个文件，想分两次提交，就 git add 文件1 文件2 只加一部分。平时用 git add .（加全部）感觉不到它的存在，但它一直在工作。

九、经验法则

  • 想”安全撤销、给别人看”→ 用 git revert（不改历史）。
  • 想”删掉自己刚犯的错”→ 用 git reset + 强推。
  • 做任何危险操作前，先 git log --oneline 记下当前位置。
  • 出了任何事，git reflog 都能找到回去的路——只要强推之前，本地记录 90 天内都能恢复。

十、.gitignore：黑名单与白名单

.gitignore 是放在仓库根目录的纯文本文件，每行一条规则，被命中的文件/文件夹 git 不再追踪、不会上传。它本身只是普通文件，记事本/VS Code/touch .gitignore 都能创建，Git 没有”创建 .gitignore”的专用指令。

基本规则

最常踩的坑：规则是完整匹配文件名的。 文件叫 git-tutorial.md，写 git-tutorial 是匹配不到的——不会自动带上扩展名，也没有”包含即命中”的模糊匹配。实测踩过：.gitignore 里写了 git-tutorial，结果文档照样被 git add . 加进暂存区，改成 git-tutorial.md 才生效。

另一个大坑：.gitignore 只对”还没被 git 追踪”的文件生效。已经 commit 过的文件，光写规则没用，要先 git rm -r --cached 路径（从追踪列表移除，磁盘文件保留），再 git add . 重新提交。

黑名单写法（默认全要，点名不要的）

思路：列出不想上传的东西，其余默认全部上传。简单直接，适合根目录本来就干净的仓库。

缺点：漏一个就翻车。以后往根目录随手放个新文件夹（临时截图、下载的压缩包），git add . 时它默认会被上传，除非你记得回来补规则。

白名单写法（默认全不要，点名要的）

如果你真实意图是”只上传指定的几样“，白名单才是贴切的写法。先用 /* 屏蔽根目录下所有东西，再用 ! 逐个放行：

逐行解读：

  • /* — 屏蔽根目录下的所有文件和文件夹。注意写 /* 而不是 *：/* 只作用于根目录这一层，配合 ! 放行才有意义。
  • ! 开头的行 — “例外/放行”，把前面被屏蔽的重新加回来。顺序很重要：! 必须写在对应屏蔽规则之后。
  • !/.gitignore — 连 .gitignore 自己都要放行。不放行的话它会被自己屏蔽掉，永远提交不了，规则就只活在你这台电脑上，换设备 clone 下来就失效了。

白名单最大的坑：被屏蔽的文件夹里，文件无法直接放行。 git 出于性能考虑，一个文件夹被整体屏蔽后，git 根本不会走进去，所以不能只放行里面的某个文件——必须先把文件夹路径放行，再放行里面的东西：

意思是：屏蔽一切 → 放行 images 文件夹本身 → 屏蔽 images 里所有内容 → 放行 images/chapters。一层一层”开门”，想放行多深的路径就要开多少层门。

注意：白名单只影响”以后新增的文件”。已经被 git 追踪的文件（之前 commit 过的）不管规则怎么写都继续被追踪，想解除还是要走 git rm --cached 那套。
