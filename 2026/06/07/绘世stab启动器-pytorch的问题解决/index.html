绘世stab启动器-pytorch的问题解决

2026年06月07日 1.7k 字 大概 7 分钟

最近玩绘世，自己的4050太拉了，跑的慢，就借用室友的电脑5050,但我的绘世是保存以前的版本，不兼容，因此出现了一些问题

一、问题背景
硬件：A 电脑（主力机） – RTX 5050 Laptop GPU + 最新驱动（支持 CUDA 13.x）

软件：秋叶绘世整合包（A 电脑），webui-user.bat 启动

目标：B 电脑（设计本）通过局域网访问 A 电脑的 SD WebUI，并使用 Photoshop pslink 插件远程出图

第一次启动绘世启动器时，弹窗警告：

当前 PyTorch 版本 2.0.1+cu118，当前显卡类型 CUDA 13030，版本不匹配，请升级 PyTorch 或更新驱动。

虽然驱动很新（理论上向下兼容），但运行 torch.cuda.is_available() 返回 True 后，实际加载模型时依然报错：

这说明 PyTorch 版本过低，不支持 sm_120 架构，必须升级到支持 CUDA 12.8 及以上的版本（如 PyTorch 2.7+cu128）。

二、核心解决方案：升级 PyTorch 到支持 RTX 5050 的版本

推荐选择 2.70+xfor0.030的版本，然后直接在绘世中安装修复，虽然慢，但不容易出错

2.1 正确版本选择
PyTorch：2.7.0+cu128（或更高，如 2.8、2.11）

TorchVision：0.22.0+cu128

TorchAudio：2.7.0+cu128

xformers：0.0.29.post3（与 2.7.0 匹配）

⚠️ 注意：截至本文，官方的 cu128 目录下已有 torch-2.7.0+cu128 稳定版，不要使用 cu118 或 cu124，它们无法驱动 sm_120。

三、其他环境问题的处理
3.1 ONNXRuntime 无法使用 GPU
绘世启动器弹出 ONNXRuntime 警告，解决方法：在启动器的”高级选项 – 环境维护”中点击”升级 ONNXRuntime”，或手动安装：

3.2 VAE 加载失败（UnpicklingError）
启动时遇到：

这是因为新版 PyTorch 默认 weights_only=True，而旧版 VAE 文件（如 animevae.pt）包含不允许的全局对象。

简单解决：移走或重命名该 VAE 文件（D:\sd-webui-aki-v4.4\models\VAE\animevae.pt -> animevae.pt.bak），使用模型内嵌 VAE，不影响出图。

彻底解决：修改 modules/sd_models.py 中的 read_state_dict 函数，将 torch.load(…, weights_only=True) 改为 weights_only=False（前提是你信任该 VAE 来源）。

3.3 绘世启动器自定义参数的正确写法
在”高级选项 – 自定义参数”中，只填写参数本身，不要写 set COMMANDLINE_ARGS=。

五、经验总结与避坑指南
RTX 50 系列必须使用 PyTorch 2.7+cu128 或更高，任何 cu118/cu124 版本均无法彻底解决 sm_120 兼容性。

不要轻信 torch.cuda.is_available() == True，它只能证明驱动和 CUDA 运行时可用，不能证明具体 kernel 可以执行。务必用真实模型加载测试。

手动下载 whl + 本地安装是解决网络慢、版本错乱的最佳实践。IDM 多线程远超 pip 单线程。

xformers 版本必须与 torch 严格匹配。使用 –no-deps 安装，防止破坏主环境。

绘世启动器的自定义参数框只写参数，不要写 set 命令。

局域网远程调用时，防火墙入站规则、–listen –api 缺一不可。若 B 电脑浏览器可以访问但 pslink 失败，尝试关闭 A 电脑防火墙临时测试，或更新 pslink 插件。

六、最终成果
A 电脑 SD WebUI 稳定运行，支持 RTX 5050 全速推理。

B 电脑通过局域网访问

Photoshop pslink 插件成功调用远程 SD 服务，实现设计 – 生成 – 迭代的远程工作流。
